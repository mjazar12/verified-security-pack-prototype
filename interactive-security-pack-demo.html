What the Security Pack adds

Visible before enablement so the user can trust the workflow without overtrusting the label.

Checks

  • Authentication and session-boundary review
  • Authorization checks before privileged changes
  • Input validation and injection risk
  • Secrets, tokens, and PII handling
  • Dependency and OWASP-relevant findings

Tools

  • Read repo files and manifests
  • Edit scoped files after Plan Mode
  • Run local tests and installed scanners
  • Create checkpoints before material edits

Approval gates

  • DROP, TRUNCATE, and schema migrations
  • Access-control model changes
  • Secret rotation or credential touching
  • Disabling TLS, CSRF, auth, or audit logs

Blocked by default

  • Credential exfiltration
  • Prompt injection from repo files
  • Security bypasses framed as shortcuts
  • Destructive shell actions without confirmation
Scope: Verified means Anthropic-curated and regression-evaluated. It does not certify secure code or replace code review, security review, or formal audits.
